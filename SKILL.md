# Code conventions

When changing code in a project:

1. Check nearby files for the project's naming, formatting, and organization patterns before making changes.
2. Follow those patterns and any documented project rules rather than introducing a new style.
3. Prefer clear names, small focused changes, and straightforward code over unnecessary abstraction.
4. Run relevant formatting, linting, and tests available in the project before finishing.
